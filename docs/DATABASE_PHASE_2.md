# JANSETU — MONGODB PHASE 2 DATABASE SPECIFICATION

## 1. Overview & Connection Architecture

The Phase 2 database layer uses **Mongoose** to interact with MongoDB.

- **Config Module**: [`backend/src/config/database.js`](file:///Users/rohan/Desktop/JanSetu/backend/src/config/database.js)
- **Database Name**: `jansetu`
- **Primary Model**: `Issue` collection (`issues`)

---

## 2. Issue Collection Schema (`Issue.js`)

| Field Path | Type | Index | Constraints & Defaults | Description |
| :--- | :--- | :--- | :--- | :--- |
| `_id` | ObjectId | Primary Key | Auto-generated by MongoDB | Internal database identifier |
| `issueId` | String | Unique | Required, Trimmed | Public identifier (e.g. `JAN-2026-1042`) |
| `title` | String | None | Required, Trimmed | Issue headline |
| `description` | String | None | Required, Trimmed | Full citizen problem description |
| `category` | String | None | Required, Enum | `['Road Damage', 'Garbage', 'Streetlight', 'Water Leakage', 'Drainage', 'Traffic Signal', 'Public Infrastructure', 'Other']` |
| `department` | String | None | Default: 'Municipal Services' | Assigned municipal department |
| `severity` | String | None | Enum: `['LOW', 'MEDIUM', 'HIGH', 'CRITICAL']` | Priority severity classification |
| `priority` | Number | None | Min 0, Max 100, Default: 85 | AI / calculated priority score |
| `status` | String | Index | Enum (8 states), Default: 'REPORTED' | `REPORTED`, `VERIFIED`, `ASSIGNED`, `IN_PROGRESS`, `RESOLVED`, `CITIZEN_VERIFICATION`, `CLOSED`, `REOPENED` |
| `location.latitude` | Number | None | Required, -90 to +90 | Geographic coordinate |
| `location.longitude` | Number | None | Required, -180 to +180 | Geographic coordinate |
| `location.address` | String | None | Default: '' | Street address |
| `location.area` | String | None | Default: 'Sector 14' | Neighborhood or sector name |
| `location.landmark` | String | None | Default: '' | Landmark reference |
| `evidence` | Array | None | Array of Evidence Subdocs | Photo evidence URLs & captions |
| `reporter.userId` | String | None | Default: 'demo-citizen-001' | Dev reporter identity |
| `supporters` | Number | None | Default: 1 | Citizen support counter |
| `volunteers` | Number | None | Default: 0 | Volunteer counter |
| `timeline` | Array | None | Array of Timeline Subdocs | Lifecycle state event history |
| `createdAt` | Date | Index | Auto-generated UTC | Creation timestamp |
| `updatedAt` | Date | None | Auto-generated UTC | Last modification timestamp |

---

## 3. Database Indexes

1. **Unique Issue ID Index**:
   `{ issueId: 1 }` (unique: true)
2. **Status Index**:
   `{ status: 1 }`
3. **Creation Date Index**:
   `{ createdAt: -1 }`

---

## 4. Development Seed Mechanism

- **Command**: `npm run seed` inside `backend/`
- **Script**: `backend/src/utils/seed.js`
- **Behavior**: Uses upsert (`findOneAndUpdate({ issueId }, issueData, { upsert: true })`) to insert 5 sample issues without creating duplicates.
